# DS4 Pad Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `F1Controller.exe --ds4` reads a DualShock 4 held flat, steers from its bank angle (nose tilt ignored), and drives the existing virtual Xbox 360 pad.

**Architecture:** New `Pad/` folder in the receiver: a pure report parser, a Madgwick port, a pure steering function, persisted settings, a HidSharp reader and a console dashboard. `Program.cs` gets a pad-mode branch that skips all phone components and feeds `XInputController` through a new pad submit method.

**Tech Stack:** .NET 8, HidSharp (NuGet), Nefarius.ViGEm.Client (existing), xunit (existing).

**Spec:** `docs/superpowers/specs/2026-10-31-ds4-pad-mode-design.md`

## Global Constraints

- All paths below are under `windows-receiver/`. Namespace for new code: `F1Controller.Pad`. Tests: namespace `F1Controller.Tests`, in `F1Controller.Tests/`.
- Run tests: `dotnet test windows-receiver/F1Controller.Tests` from the repo root.
- Defaults: lock 18°, deadzone 1°, curve 0. Ranges: lock 5–60° step 1; deadzone 0–10° step 0.5 and always < lock; curve 0–1 step 0.05.
- Full lock must reach exactly ±32767 at `bank == lock`.
- Neutral (steer 0, triggers 0, buttons up) within 100 ms of losing reports.
- Phone mode (no `--ds4`) must behave exactly as before.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Bluetooth pad still in reduced-report mode** (report ID 0x01 arriving over BT, no IMU): reader must request feature report 0x05 again, not steer from zeros → Task 5 hardware step checks reports are 0x11 on BT.
- **Pad tilted past vertical / upside down:** bank must clamp at ±90°, never wrap to the opposite lock → Task 3 test `UpsideDownDoesNotFlip`.
- **DS4 timestamp wraps** (u16, every ~350 ms): dt must stay positive and small across the wrap → Task 3 test `TimestampWrapGivesSmallPositiveDt`.
- **Deadzone pushed to or past lock with keys:** must stay < lock, no divide-by-zero → Task 4 test `DeadzoneStaysBelowLock`.
- **Console without a keyboard** (output redirected, e.g. VS Code debug console): key polling must be skipped, not throw → Task 6 guards with `Console.IsInputRedirected`.

### Task 1: DS4 report parser

**Files:**
- Create: `F1Controller/Pad/Ds4Report.cs`
- Test: `F1Controller.Tests/Ds4ReportTests.cs`

**Interfaces:**
- Produces: `readonly record struct Ds4Report(byte LX, byte LY, byte RX, byte RY, ushort Buttons, byte L2, byte R2, ushort Timestamp, short GyroX, short GyroY, short GyroZ, short AccelX, short AccelY, short AccelZ, byte Battery)` with `static bool TryParse(ReadOnlySpan<byte> report, out Ds4Report r)`. `Buttons` is already in the XUSB layout of `ControlPacket` (DPadUp 0x0001 … Y 0x8000).

Data layout, relative to data start `d` (USB report ID 0x01 → `d = 1`; BT report ID 0x11 → `d = 3`; anything else or too short → `false`):

| Byte | Content |
|---|---|
| d+0..3 | LX, LY, RX, RY |
| d+4 | low nibble d-pad hat (0 N, 1 NE, 2 E, 3 SE, 4 S, 5 SW, 6 W, 7 NW, 8 none); bit4 □, bit5 ✕, bit6 ○, bit7 △ |
| d+5 | bit0 L1, bit1 R1, bit4 Share, bit5 Options, bit6 L3, bit7 R3 |
| d+7, d+8 | L2, R2 analog |
| d+9..10 | timestamp u16 LE |
| d+12..17 | gyro X, Y, Z (i16 LE) |
| d+18..23 | accel X, Y, Z (i16 LE) |
| d+29 | battery: low nibble level 0–10 (0–11 when charging) |

Mapping: ✕→A, ○→B, □→X, △→Y, L1→LB, R1→RB, L3→LT(0x0040), R3→RT(0x0080), Options→Start, Share→Back; diagonal hats set both directions. `Battery` = min(level·10, 100).

- [ ] **Step 1: Write the failing tests** — helper `static byte[] Usb(Action<byte[], int> fill)` builds a 64-byte buffer, `[0] = 0x01`, calls `fill(buf, 1)`; `Bt(...)` builds 78 bytes, `[0] = 0x11`, `fill(buf, 3)`.
  - `ParsesSticksTriggersAndImuUsb`: LX 10, LY 20, RX 30, RY 40, L2 200, R2 255, gyro (100, -200, 300), accel (-1000, 8192, 50), battery nibble 5 → each field equal, `Battery == 50`.
  - `ParsesSameFieldsBluetooth`: same values via `Bt` → same struct as the USB case.
  - `MapsFaceAndShoulderButtons`: d+4 = 0x08 | 0x20 (hat none + ✕) and d+5 = 0x01 | 0x20 (L1 + Options) → `Buttons == 0x1000 | 0x0100 | 0x0010`.
  - `DiagonalHatSetsTwoDirections`: hat 1 → `Buttons == 0x0001 | 0x0008`; hat 8 → no d-pad bits.
  - `RejectsUnknownReportOrShortBuffer`: ID 0x05 → false; 10-byte USB buffer → false.
- [ ] **Step 2: Run** `dotnet test windows-receiver/F1Controller.Tests --filter Ds4ReportTests` → FAIL (type missing).
- [ ] **Step 3: Implement `Ds4Report.TryParse`** per the table; read i16s with `BinaryPrimitives.ReadInt16LittleEndian`.
- [ ] **Step 4: Run** the same filter → PASS.

### Task 3: Steering

**Files:**
- Create: `F1Controller/Pad/PadSteering.cs`
- Test: `F1Controller.Tests/PadSteeringTests.cs`

**Interfaces:**
- Consumes: `Ds4Report` (Task 1), `MadgwickFilter` (Task 2), `PadSettings` (Task 4 — this task defines only the three values it reads: `LockDeg`, `DeadzoneDeg`, `Curve`; if Task 4 isn't done yet, create `PadSettings` as a plain class with those three `float` properties and defaults 18 / 1 / 0, which Task 4 extends).
- Produces: `sealed class PadSteering(PadSettings settings)` with
  - `static float BankDeg(float gX, float gY, float gZ)` → `atan2(gX, sqrt(gY² + gZ²))` in degrees.
  - `static short SteerFromBank(float bankDeg, PadSettings s)` → deadzone, scale, curve, clamp, `±32767`.
  - `static float DtSeconds(ushort previous, ushort current)` → `(ushort)(current − previous) · 16 / 3 µs` in seconds.
  - `void AddBiasSample(Ds4Report r)`, `void FinishBias()` (bias = mean raw gyro of the samples).
  - `short Process(Ds4Report r)` → feeds the filter (gyro `(raw − bias) / 16` °/s → rad/s; accel raw; dt from `DtSeconds`, first report dt 0), returns `SteerFromBank(BankDeg(filter gravity), settings)`.
  - `float LastBankDeg`, `float LastAccelBankDeg` (bank from the raw accel alone, for the dashboard's sign sanity check).

Steering formula (from the spec, matches the phone's `SteeringProcessor`):

```
a = |bank|; if a < dz → 0
x = min((a − dz) / max(lock − dz, 1), 1)
x = (1 − k)·x + k·x³
out = sign(bank) · round(x · 32767)
```

- [ ] **Step 1: Write the failing tests** — helper `static (float, float, float) Grav(float bankDeg, float pitchDeg)` returns the gravity of a pad flat-up rotated by bank about Z then pitch about X: `(sin b, cos b · cos p, cos b · sin p)`.
  - `FlatIsZero`: `SteerFromBank(BankDeg(Grav(0, 0)), defaults) == 0`.
  - `FullLockAtLockAngle`: bank ±18 → ±32767; bank 30 → 32767.
  - `PitchDoesNotChangeOutput`: bank 10 with pitch 0, 30, −30 → identical `short` values.
  - `DeadzoneAndHalfway`: bank 0.9 → 0; bank 9.5 with defaults → `round(0.5 · 32767)` ±1.
  - `CurveMatchesPhone`: curve 0.5, bank 9.5 → `round((0.5·0.5 + 0.5·0.125) · 32767)` ±1.
  - `UpsideDownDoesNotFlip`: gravity (0.3, −0.95, 0) (rolled past vertical) → sign of output is +.
  - `TimestampWrapGivesSmallPositiveDt`: `DtSeconds(65500, 100)` ≈ 136 · 16/3 µs.
- [ ] **Step 2: Run** `--filter PadSteeringTests` → FAIL.
- [ ] **Step 3: Implement `PadSteering`.**
- [ ] **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `Pad: pitch-proof bank steering`.

### Task 5: HidSharp reader

**Files:**
- Modify: `F1Controller/F1Controller.csproj` (add `<PackageReference Include="HidSharp" Version="2.1.0" />`)
- Create: `F1Controller/Pad/Ds4Reader.cs`

**Interfaces:**
- Consumes: `Ds4Report.TryParse` (Task 1).
- Produces: `sealed class Ds4Reader` with `event Action<Ds4Report>? OnReport`, `bool IsConnected`, `bool IsBluetooth`, `long LastReportTicks` (`Stopwatch.GetTimestamp()`), `Task RunAsync(CancellationToken ct)`.

Behaviour: find the first HID device with VID 0x054C and PID 0x05C4, 0x09CC or 0x0BA0 via `DeviceList.Local.GetHidDevices`; open its stream (read timeout 100 ms); if any report arrives with ID 0x01 while `MaxInputReportLength > 64` (Bluetooth), call `GetFeature` on report 0x05 (buffer length = `MaxFeatureReportLength`) to switch to 0x11 reports; loop reading, `TryParse`, raise `OnReport`. On open failure, read exception or no device: `IsConnected = false`, wait 1 s, retry until cancelled.

- Create: `F1Controller/Pad/PadDashboard.cs`
- Modify: `F1Controller/Program.cs` (`--ds4` flag, usage line, pad branch)

**Interfaces:**
- Consumes: everything above; existing `XInputController`, `ControlPacket`.
- Produces: `XInputController.SubmitPad(short steer, short leftY, short rightX, short rightY, byte brake, byte throttle, ushort buttons)` — same locking and latency bookkeeping as `Submit`, sets all four stick axes. Stick conversion in Program: `axis = clamp((raw − 128) · 258, −32768, 32767)`, Y axes negated (DS4 up = 0, XInput up = positive).

Program pad branch (when `--ds4`): print the DS4Windows/JoyShockMapper warning if either process is running; create `XInputController` (same try/catch as today); load settings; start `Ds4Reader.RunAsync`; on the first connection print "Keep the pad still…", collect 1 s of reports into `AddBiasSample`, `FinishBias`; then every report → `Process` → `SubmitPad`. A 20 ms timer submits neutral when `Stopwatch` age of `LastReportTicks` > 100 ms (only once per loss) and the dashboard shows "Pad lost — reconnecting". Dashboard loop at ~15 Hz: connection, BT/USB, battery, steer %, `LastBankDeg`, `LastAccelBankDeg`, settings, key help. Keys (skip entirely if `Console.IsInputRedirected`): `[` `]` lock, `-` `=` deadzone, `,` `.` curve; each change saves settings. Phone components (UDP receiver, discovery, telemetry, engineer, radio) are not created in pad mode.
